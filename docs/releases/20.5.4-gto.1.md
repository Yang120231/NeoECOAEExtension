## 中文

**Minecraft 1.20.1 / Forge · GregTech Odyssey 专用预发布版**

Neo ECO AE Extension **20.5.4-gto.1**，面向 GTO `0.6.0-dev25`（Dev25），编译依赖固定为 GTO AE2 **15.2610.31**。目标实例使用 Java 21。

### 合成与批量发配

- 同一任务内，成功发配的配方持续优先；缺料、供应器拒收、任务完成、暂停或依赖与循环约束阻塞时，再尝试其他合法配方。每 tick 的执行与探测预算继续生效。
- 加工批量预算改按向供应器提交的次数计算，移除每 tick 一百万份的数量上限。支持容量协商的 GT 缓冲按实际容量接收批量，可处理超过 `Integer.MAX_VALUE` 的份数；材料、能量、任务余量和循环启动要求仍限制批量。
- 每个 CPU 每 tick 最多进行 64 次批量加工提交尝试，单个配方最多使用其中 32 次，为其他就绪配方保留调度机会。预算耗尽不再误记为供应器失败或触发退避。
- 修正大批量探测记忆的倍增计算，避免已确认的大批量因整数上限而缩小或溢出。
- 修正循环规划：库存中间原料按需求直接消耗，只补实际缺口，不额外加工以恢复原库存或保留种子。启动材料仍须实际可用，催化剂和容器仍遵循样板返回规则。
- 优化规划、执行和合成图布局中的集合处理。

### 无限存储与多方块预览

- 无限存储迁移采用驱动器共享的 tick 时间与资源种类预算，新增迁移进度和受阻原因提示。
- 存储列表支持增量更新，合并驱动器持久化通知，减少重复遍历和无变化同步。
- 更新 JEI/EMI 多方块预览面板，支持长度、分层和成型预览，材料区按整行滚动，并展示对应结构的容量、并行、线程或合成速度信息。
- 修复工作站成型预览模型缺失、材料数量显示及 JEI 页面高度问题，补齐六种语言和中英文指南。

## English

**Minecraft 1.20.1 / Forge · GregTech Odyssey prerelease**

Neo ECO AE Extension **20.5.4-gto.1**, targeting GTO `0.6.0-dev25` (Dev25), with compilation pinned to GTO AE2 **15.2610.31**. The target instance uses Java 21.

### Crafting and batch dispatch

- Keep a successfully dispatched pattern preferred within its job until inputs run out, providers reject it, the task completes, the step is paused, or dependency and cycle constraints block it. Per-tick execution and probe budgets still apply.
- Budget processing batches by provider submission attempts, removing the former one-million-crafts-per-tick limit. GT buffers with negotiated capacity accept batches up to their actual capacity, including counts above `Integer.MAX_VALUE`; materials, energy, remaining work and cycle startup requirements still bound each batch.
- Allow at most 64 batch-processing submission attempts per CPU per tick, with at most 32 for one pattern, reserving opportunities for other ready patterns. Budget exhaustion no longer counts as a provider failure or triggers backoff.
- Fix probe growth for remembered large batches so integer limits cannot shrink or overflow a proven batch size.
- Correct cycle planning to consume intermediate stock as needed and produce only actual shortfalls, without extra crafting to restore stock or retain seeds. Startup materials must still exist, and catalyst and container returns still follow the pattern.
- Optimize collections used by planning, execution and crafting graph layout.

### Infinite storage and multiblock previews

- Share per-tick time and resource-type migration budgets across infinite storage drives, displaying migration progress and blocked reasons.
- Update storage listings incrementally and coalesce drive persistence notifications to reduce repeated scans and unchanged synchronization.
- Update JEI/EMI multiblock previews with length, layer and formed controls, row-based material scrolling, and capacity, parallelism, thread or crafting speed information for the displayed structure.
- Fix missing formed workstation models, material counts and JEI page sizing; update six locales and the Chinese and English guides.

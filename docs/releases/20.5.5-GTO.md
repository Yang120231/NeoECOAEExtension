## 中文

**Minecraft 1.20.1 / Forge · GregTech Odyssey 专用正式版**

Neo ECO AE Extension **20.5.5-GTO**，延续 GTO Dev25 专版适配，编译依赖固定为 GTO AE2 **15.2610.31**，目标实例使用 **Java 21**。以下更新相对于 `20.5.4-gto.1`。

### 修复

- 修复计算子系统通讯接口过滤槽点击、拖拽时可能复制物品或使不可堆叠物品异常叠加的问题，继续支持 JEI/EMI 幽灵样本。
- 修复自增殖循环的保种规划：保留最小启动种子，允许循环借用并归还；缺少启动材料或燃料时仍正确报告缺料。
- 补全副产物的生产路线。副产物不足时会追加所需原料和上游加工次数，同时保留 AE2 主产物与既有生产线顺序的优先级。
- 清理副产物造成的纯排序环，改进物料不足判定与替代路线搜索预算，减少无效搜索和异常膨胀的加工次数。
- 修复智能翻倍样板跨实例匹配失败导致批量发配退化的问题。

### 界面与性能

- 合成主机并行、队列、FX/FT 与无限模式提示改为统计卡片，展示容量、使用情况、溢出比例和生效超频等信息。
- 计算主机增加 CPU 存储、线程、并行统计卡片及 CPU 行、合成状态物品卡片；CPU 行按住 Shift 可查看精确数值。容量单位使用 KB 至 EB，保留机器状态和加工步骤提示。
- CPU 待合成数量改为一次汇总并缓存，减少大订单打开或刷新界面时的重复扫描。
- 同步智能翻倍闪电图标，补齐六种语言的卡片文本，并修复无客户端窗口时读取 Shift 状态的问题。

### 合成计划导出

- 新增管理员命令 `/neoecoae export_plan`（权限等级 2），导出执行命令后打开的下一次合成计算结果。
- 报告包含网络样板、生产顺序、物料收支和循环诊断，保存在服务端存档的 `eco-plan-exports` 目录。

### 安装与验证

- 客户端和服务端均安装 `neoecoae-20.5.5-GTO.jar`，移除旧版 NeoECOAE JAR，两端版本须一致。`-sources.jar` 为开发者源码包，`SHA256SUMS.txt` 用于校验下载文件。
- 本地模组包、源码包构建与发布 JAR 检查通过，版本元数据已核对。GTO 专题测试 **86 项：83 项通过、3 项跳过、0 失败**；跳过项需要提供目标实例的 AE2/GTOCore JAR。
- 使用临时独立测试入口运行本次变更相关的合成规划、循环保种、物料证明、计划导出、样板匹配与提示卡片回归，**73 项全部通过**。
- 本次未进行开发客户端、完整 GTO 实例、独立专服或普通安装验收；旧测试套件与 GTO API 的既有兼容问题不代表已解决。

## English

**Minecraft 1.20.1 / Forge · GregTech Odyssey stable release**

Neo ECO AE Extension **20.5.5-GTO**, continuing the GTO Dev25 adaptation. Compilation is pinned to GTO AE2 **15.2610.31**; the target instance uses **Java 21**. Changes below are relative to `20.5.4-gto.1`.

### Fixes

- Fix item duplication and invalid stacking of unstackable items when clicking or dragging computation interface filter slots. JEI/EMI ghost samples remain supported.
- Correct seed retention for self-replicating crafting cycles: reserve the minimum startup seed, allow cycles to borrow and return it, and report missing startup materials or fuel.
- Complete byproduct production routes, adding upstream materials and processing runs for actual shortfalls while preserving AE2 primary-output and existing production-line priorities.
- Remove ordering-only byproduct cycles and improve material infeasibility checks and alternative-route search budgets, reducing wasted searches and inflated processing counts.
- Fix equivalent smart-doubling patterns from different instances failing to match and degrading batch dispatch.

### Interface and performance

- Replace crafting host parallelism, queue, FX/FT and infinite-mode tooltips with cards showing capacity, utilization, overflow and effective overclock information.
- Add computation host CPU storage, thread and parallelism cards, CPU row cards and crafting-status item cards. Hold Shift on CPU rows for exact values. Capacity units use KB through EB; machine status and processing-step information are retained.
- Aggregate and cache CPU pending outputs once, reducing repeated scans when opening or refreshing large orders.
- Update the smart-doubling lightning icon, complete card text in six locales, and guard Shift detection when no client window exists.

### Crafting plan export

- Add `/neoecoae export_plan` for administrators (permission level 2), exporting the next crafting calculation opened after running the command.
- Reports include network patterns, production order, material balances and cycle diagnostics, saved under `eco-plan-exports` in the server world directory.

### Installation and verification

- Install `neoecoae-20.5.5-GTO.jar` on both client and server, removing older NeoECOAE JARs. Both sides require the same version. The sources archive is for developers; `SHA256SUMS.txt` provides download checksums.
- Local mod and sources builds, artifact checks and version metadata verification passed. Of **86 focused GTO tests, 83 passed, three were skipped and none failed**. Skipped checks require the target instance's AE2/GTOCore JARs.
- An isolated temporary test task ran **73 selected regressions, all passing**, covering crafting planning, cycle seeds, material proofs, plan export, pattern matching and tooltip cards.
- The development client, full GTO instance, standalone dedicated server and ordinary installation were not verified for this release. Existing incompatibilities between the legacy test suite and GTO APIs remain outside this release preparation.
